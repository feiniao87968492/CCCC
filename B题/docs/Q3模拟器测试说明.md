## 2. 官方模拟器是什么

可执行文件（相对 `simulator_automation/`）：

```text
../../Jammers-simulator-full-win64/Jammers-simulator-full/jammers-simulator-full.exe
```

窗口标题：`无线电干扰源环境模拟器`。版本曾实测 **v1.1**。必须联网；同一队号不能多设备同时在线。

Q3 局内设定（题面，接口不返回真值）：

- 全向源，\(N\in[10,16]\) 在线未知
- 机器狗从 \((0,0)\)、频道 1 出发
- 虚拟时限 360000 s；现实 `/enter` 后约 1200 s
- 目标：先全部清除，再缩短虚拟总时间 \(T\)
- 演练结束给 \(N\)（可算 \(K/N\)、\(T/K\)）；正式测试永不给 \(N\)，论文表 1 只有案例编码、\(K\)、\(T/K\)、程序运行时间

Q3 与 Q4 正式额度**各 3 次**，中止也占次。截止：北京时间 2026-09-13 17:30 后不能启动新测试。

## 4. 官方接口（Q3 测试的真正 I/O）

默认 `http://127.0.0.1:2026`。仅 4 条 POST：`/enter` `/measure` `/clear` `/exit`。没有单独“移动”指令，坐标写在 measure/clear 的 `position` 里。

客户端：`simulator_automation/robot_client.py` 的 `RobotClient`。

约定：

- 队号默认 `202611102016`（`robot_id`）
- 每动作新 `request_id`；网络重试最多 3 次且**必须复用同一请求体和 ID**
- `accepted=false` 或 HTTP 错误立即停
- 坐标每分量绝对值 \(\le 2\times 10^6\)，允许出 1800 m 圆
- 频道 1–20；**只有 `/measure` 改测向机频道**；`/clear` 的频道不改寄存器
- `/enter` 返回 `remaining_real_duration_s`；客户端按此设截止，默认提前 5 s 拒绝再发 measure/clear
- 虚拟时间由模拟器累加，**不必现实 sleep 等 5 秒检测**

`/measure` 三值：`near` | `direction`（带 `svd_deg`，真方位 \(\pm 1^\circ\)，两位小数）| `no_signal`。  
`/clear`：成功或 `no_target_in_range`。光学清除半径 20 m，与测向朝向无关。

计时（与 `virtual_time_s` 对账）：

- measure：\(\|q-p\|/5 + 1_{\text{切频}} + 5\)
- clear：\(\|q-p\|/5 + 3 + 2\cdot 1_{\text{成功}}\)
- enter/exit 不加虚拟时间

Q3 的 `no_signal`：无源 / 超出该源 \(r_i\ge 1000\)。单点无信号不能证无源。Q4 另有扇外，**不要把 Q3 距离排除搬到 Q4**。

禁止：读隐藏真值、改模拟器数据文件、用 RSSI、把 10 个清除当结束、未授权点正式测试。

## 4. 当前自动化怎么跑

两层：

1. **UI（PowerShell + UI Automation）** `ui.ps1`  
   启动/附着 exe、登录（密码在脚本本地明文，按仓库既有约定）、点「问题3 演练」、等倒计时到“等待机器狗进入”。不依赖鼠标坐标或 Playwright。
2. **HTTP 冒烟** `smoke.py`  
   固定 6 步，**不是求解器**：

   `/enter` → 原点 ch1 measure → 原点 ch2 measure → 原点 ch1 clear → 原点 ch2 measure → `/exit`

一键（在 `B题` 目录）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\simulator_automation\run_practice.ps1 -Problem 3
```

需要已解锁的 Windows 交互会话。不要在脚本运行时手点测试页。最小化窗口曾导致 UIA 树为空，脚本会 `ShowWindow` 恢复。

接入策略时：先 UI 把演练开到“等待进入”，再自己 `RobotClient.enter()` 后循环 measure/clear，最后 `exit()`。模板见 `simulator_automation/README.md`。将策略放在该目录或把该目录加入 `sys.path`。

## 7. 其他 agent 的硬规则

1. **默认只动演练。** 正式 3 次须用户书面授权后再点。
2. **不要跑 smoke 当策略评估。** 它会在原点乱 clear，且 Inspect 保护只认演练页。
3. **不要用** `q2_validation` / 种子生成器里的 \(g,r\) 去调模拟器动作。
4. 墙钟 1200 s 与虚拟 360000 s 分开；FAST 省的是 CPU，不自动等于虚拟 \(T\) 更短。
5. 演练结束后看到的 \(N\) 只用于事后表，禁止写进下一局在线终止器。
6. `ever_detected=16` 才可取消剩余发现任务；清满 10 个不能 `/exit`。
7. 改模拟器路径、端口、队号时同步 `ui.ps1` / `--port`。exe 与数据目录要一起搬。
8. 题目窗口截止后不要启动新测试。

## 8. 若要真正做“Q3 模拟器测试”该补什么

按顺序，且每步仍是演练直到用户授权正式：

1. 协议替身或短演练：成功 `near`/`clear`、移动后 `virtual_time_s` 与公式一致、拒绝动作不破坏状态。
2. Q3 闭环 runner：七点集合 + 动态顺序 + 四套定位之一 + SAFE 兜底 + 预算内 `/exit`。
3. 同案例对比 SAFE_ONLY / ROBUST / FAST / HYBRID（演练可重复；正式不可为对比浪费次数）。
4. 充分演练后再申请 3 次正式；导出未改名 `.jlog`。

未完成以上任何一步，都不得在论文或验收里写 Q3 模拟器清除率、平均时间或“策略已验证”。
